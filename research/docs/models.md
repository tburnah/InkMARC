## Provenance and use

The depth proxy mixed-full export JSON identifies its best-validation checkpoint;
the quantisation JSON records unsigned 16-bit activations, unsigned 8-bit weights
and 512 calibration frames. These existing records are copied without interpreting
their recorded numerical comparisons as newly run checks.

The sensing family retains distinct best-loss, best-location, best-state, best-touch,
latest and deployable artifacts. The two best-xy initializers referenced by the
combined config are retained. The five CV `latest.pt` files are retained because
the saved commands explicitly reference them. Dataset manifests and participant
predictions are withheld. No checkpoint is selected solely because it is newest.

Strict/balanced selection pointer JSONs and their original checkpoint paths are
retained, along with the corresponding selected copies and sensing deployment pairs.
Equal-sized files are not assumed identical or deduplicated.

The shared output location is storage provenance, not proof that the earlier
`inkdepth_student` source snapshot produced later workspace artifacts.

## Large-file handling

Every selected binary in this candidate is below 100 MiB. No Git LFS configuration
or migration has been applied. Some held historical depth/Keras/teacher files exceed
the ordinary GitHub file limit; distribution must be decided if those are selected.
GitHub documents its limits and release/LFS alternatives in
[About large files](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github).

The full unselected model inventory stays in `review-only/checkpoint-candidates-held.json`
outside the publication root. Models remain candidates for author release approval.

[Model interfaces](../provenance/model-interfaces.json) records existing ONNX input/output names, tensor shapes, opsets and schema-check outcomes. No inference or conversion was performed.
